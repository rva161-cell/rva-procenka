# Артикул-бот — бот магазина запчастей (Python)

Подпроект сайта. Два транспорта одного ядра: **MAX** (`max_bot.py`, работает без VPN —
основной) и **Telegram** (`bot.py`, aiogram 3). Вся логика диалога — в `core/dialog.py`,
поэтому оба бота ведут себя одинаково: правка в одном месте действует сразу в обоих. Пользователь получает меню сервиса,
присылает **фотографию запчасти** — бот определяет, что это, предлагает артикул, **сверяет его
по базам поставщиков** и после подтверждения показывает мини-проценку.

## Уровни доступа

Бот публичный (ссылки на сайте и в общем доступе), поэтому выдача зависит от уровня
пользователя. База одна — `procenka/data.db` (SQLite) на сервере проценки; бот спрашивает
уровень по HTTP (`POST /api/bot/user`) и кэширует на 5 минут. Сервер недоступен →
пользователь считается гостем (показываем меньше, а не больше).

| Уровень | Кто это | Что видит в боте |
|---|---|---|
| 1 — гость | все остальные | поиск артикулом текстом: топ-10 строк, цена ×1.2, склады и сроки — да, поставщики — скрыты; фото — заглушка |
| 2 — зарегистрирован | регистрация на сайте (этап 4, VPS) | как гость + комментарии, аудит/консультация |
| 3 — свои поставщики | заявка на странице проценки одобрена | **поиск по фото** + проценка по его поставщикам и ценам без ограничений |
| 4 — близкий | `procenka/close_people.json` или админ | всё + будущие функции |

Привязка аккаунта к мессенджеру — по номеру телефона, **только кнопкой** «📱 Отправить контакт»
(request_contact). Бот проверяет, что контакт принадлежит отправителю: в Telegram —
`contact.user_id == from_user.id`, в MAX — подпись `hash` (HMAC-SHA256 от `vcf_info`, ключ —
токен бота). Номер, набранный текстом, и пересланный или выбранный из записной книжки контакт
не принимаются: иначе, зная чужой телефон, можно получить чужой уровень доступа.
Телефон спрашивается при регистрации на странице проценки. Правки `close_people.json`
вступают в силу сразу, без перезапуска сервера.

Гостевые правила (наценка 1.2 и лимит 10 строк) задаются в `config.json → levels`
и применяются в боте к выдаче из любого источника (включая фолбэк Поставщик) —
сырые закупочные цены наружу не уходят. Проверка: `venv/bin/python cli.py --rules`.

Сервер проценки отдаёт сырую выдачу (`/api/brands`, `/api/search`) только боту с ключом
`X-Bot-Key` и одобренным пользователям сайта. Без ключа бот получит гостевую выдачу сервера —
это значит, что `BOT_API_KEY` в `bot/.env` и `procenka/.env` разошёлся.

## Возможности

Меню — кнопкой «МЕНЮ» под каждым сообщением (в MAX и в Telegram одинаково):

- ⌨️ **Ввод артикула** — артикул текстом (или просто написать его в чат, или голосом); несколько брендов → выбор; → топ-3 предложения с правилами уровня
- 📸 **Фото запчасти** (с 3 уровня) — кандидат → «✅ Верно / ❌ Не то / 🔄 Другие варианты» → проценка
- 📰 **Мысль дня** (админ сайта или директор) — карточка → обработка по промту → черновик истории (можно заменить своим текстом) → «Разместить» в ленте
- 👥 **Пригласить друга** — персональный QR и ссылка; за каждых 10 приглашённых −2% (максимум 10%)
- 📰 **Лента** — последние 5 карточек
- 📝 **Регистрация на сайте** — ссылка, когда задан `SITE_URL`
- ❓ **Задать вопрос** — вопрос сохраняется на сервере проценки (виден в `/кабинет` у админа)
- 📱 **Привязать аккаунт** — только кнопкой «Отправить контакт» (в Telegram она появляется на нижней клавиатуре)

Старые кнопки нижней клавиатуры Telegram («🔍 Найти артикул», «💰 Проценка», «🌐 Сайт» и т.д.)
у тех, у кого они остались, продолжают работать.

## Как это работает

```
фото (уровень 3+) → GLM-4.6V (api.vision-ai.example) распознаёт бренд/продукт/коды/штрихкод
     → коды-кандидаты сверяются с базами:
         1) программа проценки (../procenka, все поставщики)
         2) фолбэк: сайт Поставщик напрямую (без ключа)
     → бот показывает кандидата («✅ подтверждён по базе» / «⚠️ предположение»)
     → пользователь подтверждает → предложения по правилам уровня
```

Модель **не может выдать непроверенный артикул как надёжный**: без совпадения в базе
кандидат помечается «⚠️ предположение распознавания».

## Окружение и зависимости

Python 3.11+, виртуальное окружение уже создано в `venv/`:

```bash
source venv/bin/activate        # активация (в каждой новой сессии терминала)
python max_bot.py               # основной бот — MAX (работает без VPN)
python bot.py                   # бот Telegram
deactivate                      # выход из окружения
```

Можно и без активации: `venv/bin/python max_bot.py`, `venv/bin/python cli.py --rules`.

Зависимости ставились так (уже выполнено, повторять не нужно):
`python3 -m venv venv && venv/bin/pip install -r requirements.txt`

## Настройка — файл `.env` (в папке проекта)

```ini
TELEGRAM_TOKEN=1234567890:AA...   # @BotFather в Telegram → /newbot
MAX_TOKEN=                        # business.max.ru → Чат-боты → создать → Настройки → «Получить токен»
VISION_API_KEY=                   # ключ API на vision-ai.example, модель glm-4.6v (тариф API, не подписка)
BOT_API_KEY=секрет                # ОБЯЗАТЕЛЕН: тот же, что в procenka/.env (бот-API и полная выдача)
# SITE_URL=https://ваш-домен/                  # кнопка «🌐 Сайт»
# PROCENKA_PUBLIC_URL=https://poisk.ваш-домен/ # кнопка «💰 Проценка»
```

Значения — без кавычек. Приоритет: переменные окружения → `.env` → `config.json`.
После правок бота перезапустить. Для полной проценки рядом запустите
`cd ../procenka && node server.js` (иначе проверка и цены — только через Поставщик).

Сервер проценки читает `BOT_API_KEY` из `procenka/.env` (или из окружения). Ключ уже
сгенерирован и прописан в оба `.env` (19.10.2026). Без ключа сервер **закрывает** бот-API:
привязка, уровни, вопросы и приглашения не работают, бот считает всех гостями. Для отладки
без ключа — `BOT_API_OPEN=1` в `procenka/.env` (на VPS не включать).

Регистрация на странице проценки теперь требует телефон — по нему бот привязывает
аккаунт. У тех, кто зарегистрирован раньше, телефона нет: пусть впишут его в личном
кабинете (`/кабинет` → профиль) или перерегистрируются.
Уровень 4 («близкий») — список в `procenka/close_people.json` (образец:
`close_people.example.json`), правки действуют сразу.

## Проверка без мессенджеров

```bash
venv/bin/python cli.py --all              # все *.jpg из папки: распознавание + сверка
venv/bin/python cli.py --all --offers     # + топ-3 предложения
venv/bin/python cli.py IMG_20261012_211526.jpg
venv/bin/python cli.py --code 110800      # поиск по коду (работает без vision-ключа)
venv/bin/python cli.py --rules            # правила уровней (наценка, лимит, скрытие поставщиков)
venv/bin/python cli.py --dialog           # сценарии диалога (25 проверок) — без сети и мессенджеров
```

`--dialog` прогоняет диалог по сценариям (старт по приглашению, артикул, выбор бренда,
фото по уровням, привязка своим и чужим контактом, вопрос, «Мысль дня», приглашение,
ошибки) с заглушками вместо сервера и мессенджеров. Запускайте после любой правки
`core/dialog.py` или `core/present.py`.

Проверка бот-API сервера проценки (сервер должен быть запущен, ключ — из `.env`):

```bash
KEY=$(grep '^BOT_API_KEY=' .env | cut -d= -f2)
curl -s -X POST http://127.0.0.1:8766/api/bot/user -H "X-Bot-Key: $KEY" \
     -d '{"transport":"max","tid":"123"}'            # → {"found":false,"level":1,...}
curl -s -X POST http://127.0.0.1:8766/api/bot/user \
     -d '{"transport":"max","tid":"123"}'            # без ключа → {"error":"Неверный ключ бот-API"}
```

## Если бот не запускается: «Не удалось связаться с Telegram… таймаут»

`api.telegram.org` может быть недоступен у вашего провайдера (с Mac директора так и есть —
проверено 12.10.2026). Варианты:

1. включить VPN на время работы бота;
2. указать прокси в `.env`: `TELEGRAM_PROXY_URL=http://host:port`
   (для `socks5://…` — сначала `venv/bin/pip install aiohttp-socks`);
3. развернуть бота на VPS (Timeweb, как планировали для проценки) — там обычно доступно.

## Структура

- `core/dialog.py` — **весь диалог** (меню, поиск, фото, проценка, лента, приглашения, привязка, вопросы), общий для MAX и Telegram; сессии пользователей — в памяти
- `max_bot.py` — транспорт MAX (platform-api2.max.ru): long polling, дедупликация, скачивание вложений, проверка подписи контакта, кнопки MAX; **основной бот**. Здесь же `DIRECTOR_IDS` — MAX-id директора
- `bot.py` — транспорт Telegram (aiogram 3): приём сообщений, скачивание файлов, проверка своего контакта, кнопки Telegram
- `core/levels.py` — уровни доступа: запрос к серверу проценки, правила гостя (наценка/лимит/скрытие), привязка по телефону
- `core/present.py` — общие тексты и форматирование (то, что одинаково в MAX и Telegram)
- `core/config.py` — конфиг: config.json + .env + переменные окружения
- `core/vision.py` — запрос к GLM-4.6V, строгий JSON-промпт, защита от выдуманных артикулов
- `core/verify.py` — сверка по проценке + фолбэк Поставщик, кэш 10 минут
- `cli.py` — офлайн-тесты конвейера
- `venv/` — виртуальное окружение Python (на VPS не копируется — создаётся заново)
- `logos/` + `make_logo*.py` — логотипы RVA и скрипты, которыми они сгенерированы
- Фото `IMG_*.jpg` — тестовые снимки канистр масел (NGN, AUTOBACS)
- Прежняя версия бота на Node.js — в `_archive/бот_node_версия` (референс)

Серверная часть уровней — в `../procenka`: база `data.db`, таблица `users` (телефон, max_id,
telegram_id, уровень), `close_people.json`, `POST /api/bot/user` и `POST /api/bot/link` в `server.js`.
