# Сайт ГСМ эксперт с платформой проценки по артикулу и ботами для пользователей

**ГСМ эксперт**

**Технический аудит на предприятии** — глубокая ревизия применения
смазочных материалов на заводах, в автопарках и агрохолдингах: условия
хранения, логистика перемещения, фактическая применяемость масел в узлах
и чистота процедур замены — а не только «бочка в цеху».

**Проценка по артикулу.** Покупатель вводит артикул — сервис одновременно
опрашивает поставщиков, собирает цены, сроки и наличие, показывает
аналоги (кросс-номера) и сортирует по цене. Работает как веб-сайт, как
страница проценки и как чат-боты в MAX и Telegram.

## Демо

Работающий сайт: **https://rva161.ru** — гостевой доступ открыт: можно искать
артикул и смотреть цены и сроки без регистрации (с лимитом запросов).
Страница проценки — кнопка «Проценка» на главной.

## Возможности

- **Автопроценка по поставщикам** — 10+ поставщиков опрашиваются напрямую,
  плюс прайс-листы из файлов и «браузерная» проценка для сайтов без
  программного доступа (headless Chrome + локальная LLM).
- **Две волны поиска** — сначала «возможные запросы» (бренды по артикулу, с
  группировкой по поставщикам), затем предложения по выбранному бренду; кэш
  ответов, статусы каждого поставщика, авто-повтор при лимитах транзитных.
- **Аналоги (кроссы)** — переключатель «точный артикул / с аналогами», у
  каждого поставщика своё написание бренда и свой идентификатор позиции.
- **Массовая проценка** — загрузка XLS/CSV со списком артикулов.
- **Поиск по фотографии** — снимок детали распознаёт локальная мультимодальная
  модель (LM Studio на своём железе, без внешних ИИ-сервисов), с очередью
  и быстрой моделью для чётких артикулов.
- **Личные списки поставщиков** — у каждого пользователя с полным доступом
  свой набор поставщиков со своими логинами (изоляция поиска и кэша).
- **Уровни доступа L1–L5** — от гостя с лимитом запросов до полного доступа,
  регистрация по приглашению с подтверждением администратором.
- **Боты MAX и Telegram** — мини-проценка, голосовой ввод, «Мысль дня»,
  админ-пульт служб сервера (статус/ошибки/рестарты прямо из бота).
- **Органайзер (PWA)** — задачи с получасовым календарём, книжка, сканы с
  распознаванием и выгрузкой на Яндекс.Диск; почта — входящие письма и
  заказы-заявки от бота пользователя автоматически попадают в календарь
  для выполнения.
- **Эксплуатация** — PostgreSQL, HTTPS (nginx), systemd-службы, сторож,
  отчёт в 9:00, бэкапы на Яндекс.Диск по расписанию.

## Стек

| Слой | Технологии |
|---|---|
| Сервер | Node.js без фреймворков (`procenka/server.js`), PostgreSQL |
| Сайт | Ванильные HTML/CSS/JS, PWA-манифест для органайзера |
| Боты | Python (MAX и Telegram), общий диалоговый модуль |
| ИИ | LM Studio — локальные LLM/VLM (распознавание фото, черновики) |
| Инфраструктура | nginx, systemd, rsync-деплой, PostgreSQL, бэкапы на Яндекс.Диск |

## Структура репозитория

| Папка | Что это |
|---|---|
| `site/` | Сайт: варианты главной и посадочные страницы |
| `procenka/` | Сервер проценки (Node.js, порт 8766): поиск, поставщики, сайт проценки |

## Как идёт поиск

```
пользователь (сайт / бот / XLS)
        │  артикул
        ▼
  сервер проценки ── 1-я волна: бренды по артикулу у всех поставщиков (параллельно)
        │                 └─ группировка написаний бренда, pid своего поставщика
        ├─ 2-я волна: предложения по бренду (аналоги по галочке)
        ▼
  сортировка по цене → выдача с наценкой для гостей, статусы поставщиков
```

Ответы кэшируются (по умолчанию 10 минут; при ошибке поставщика — 1 минута),
поэтому повторные запросы не тратят квоты поставщиков. Ошибки каждого
поставщика видны в строке статуса, штатные отказы (например, поставщики без
подбора бренда) показываются нейтрально, не как ошибки.

## Запуск (локально)

```bash
cd procenka
npm install
node server.js        # http://127.0.0.1:8766
```

Для полноценной работы нужны (в репозиторий не входят, в `.gitignore`):
`procenka/.env` (ключи доступа), `procenka/suppliers.json` (поставщики с
логинами), PostgreSQL и настроенные боты (`bot/.env`). На сервере всё
поднимается скриптами из `deploy/` (nginx, systemd, бэкапы, сторож).

## Конфиденциальность

Секреты (ключи доступа, пароли поставщиков, доступы сервера) и персональные
данные пользователей в репозиторий не попадают — они живут в файлах вне git
на своём сервере. Файлы-примеры: `close_people.example.json`,
`mailboxes.json.example`.
