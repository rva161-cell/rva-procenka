ПРОМТ: ОРГАНАЙЗЕР RVA (черновик для утверждения директором, 20.10.2026)
Основа: вариант «А» — раздел на существующем сервере проценки. Облачные сервисы
(Битрикс24, Notion, Todoist) не используются; Яндекс.Задачи/Календарь — только запасной
путь, если свой органайзер не взлетит (решение 20.10).

0. ОБЩЕЕ
0.1. Органайзер живёт на существующем сервере (procenka, Node.js + node:sqlite) как
     раздел /organizer. Отдельной базы и отдельного входа НЕТ — та же учётка, что на
     сайте и в ботах.
0.2. Доступ — 5-й УРОВЕНЬ: отдельный список-таблица в стиле close_people.json — правится
     ВРУЧНУЮ (директор сам вносит людей), действует без перезапуска сервера. В нём
     директор и ещё 1–2 человека; позже — кнопка в админке. Существующие уровни 1–4
     не трогаются (их пересмотр — отдельная беседа). Без 5-го уровня раздел не
     открывается даже из прямой ссылки.
0.3. На главной странице сайта для тех, у кого доступ есть и кто вошёл, — кнопка/иконка
     «Органайзер». Гостям кнопки не видно.
0.4. Безопасность и бэкапы — с первого этапа (раздел 8), не «потом».

1. ПОСТУПЛЕНИЯ (откуда берутся задачи)
1.1. Рабочий почтовый ящик — info@vredkin.ru (IMAP): фоновый конвейер по образцу
     lenta_bot.py, опрос раз в 1–2 минуты. Письмо клиента → новая задача: отправитель,
     тема, текст, вложения прикрепляются к задаче. Спам и корзина не попадают. Письмо
     помечается прочитанным только после успешного создания задачи (сбой — письмо
     остаётся на месте, повтор). АВТО-КОНТАКТЫ И СКЛЕЙКА (4.2) работают ТОЛЬКО для
     писем, поступивших на info@vredkin.ru.
1.2. Личный ящик директора (и в будущем — по одному у каждого пользователя organайзера):
     второй конвейер с теми же правилами, настраивается отдельно в настройках органайзера
     (IMAP-адрес, логин, пароль приложения). Пароли в git не попадают.
1.3. Боты (MAX и Telegram): «Задать вопрос» — уже сохраняет вопрос; дополнительно он
     создаёт задачу с пометкой источника (MAX/Telegram) и ссылкой на пользователя, если
     аккаунт привязан. Артикул в письме или вопросе — в тексте задачи, тип «Закупка».
1.4. Ручной ввод: кнопка «+ Задача» в органайзере.
1.5. У каждой задачи — метка источника: почта (какой ящик), бот, вручную.

2. ЗАДАЧИ
2.1. Поля: заголовок, текст, источник, контакт-автор, дата создания, срок (дата и,
     по желанию, время), отметка «Выполнено», вложения, история изменений.
2.2. «Выполнено» — галочка: активировал → задание снято (ушло в архив, видно кто и
     когда закрыл; можно вернуть обратно).
2.3. Списки: «Входящие» (новые), «Сегодня», «По контактам», «Архив», поиск по тексту.
2.4. АВТОПЕРЕНОС: невыполненные задачи с вчерашней и более ранней датой автоматически
     переносятся на сегодня (ежедневная сверка + проверка при первом открытии за день).
     Факт переноса виден (значок и счётчик «перенесено N раз»).

3. КАЛЕНДАРЬ
3.1. Каждая задача одновременно показывается в календаре на своей дате.
3.2. Вид дня: часовые строки (например 7:00–21:00), задачу можно ПЕРЕТАЩИТЬ на нужное
     время; перетаскивание на другой день меняет дату. Вид недели — сетка дней.
3.3. Задача без времени стоит в «Весь день»; после перетаскивания получает время.
3.4. Автоперенос (2.4) работает и в календаре: не выполнено до конца дня → завтра.

4. КНИГА КОНТАКТОВ
4.1. Основа — зарегистрированные пользователи (уже в базе): имя/логин, email, телефон,
     уровень, мессенджер и его id.
4.2. Письма от незарегистрированных клиентов (только info@vredkin.ru): контакт
     создаётся автоматически из адреса и имени отправителя; если позже человек
     регистрируется и привязывает бота — записи склеиваются по email/телефону.
4.3. Из задачи доступны действия с автором:
     — 📞 Позвонить (ссылка tel:, на телефоне сразу звонок);
     — ✉️ Письмо (mailto: с подставленной темой по задаче);
     — 💬 Сообщение — НА ВЫБОР канала: через MAX-бота, через Telegram-бота или email.
        Сообщение уходит от имени бота пользователю (если он в боте), иначе — письмо.

5. ЗАПИСНАЯ КНИЖКА
5.1. КНИЖКА ПЕРСОНАЛЬНАЯ: у каждого пользователя 5-го уровня — своя книжка: свой
     алфавит, своё содержание, свои записи. Чужие книжки не видны (совместный доступ —
     не делаем, если понадобится — добавим).
5.2. Первая страница книжки — алфавит: русские А–Я и английские A–Z (две группы,
     крупные плитки-буквы).
5.3. Страница буквы — СОДЕРЖАНИЕ: список записей на эту букву, по алфавиту, растёт сам
     по мере накопления. Из содержания — переход в любую запись/документ.
5.4. Запись: название, произвольный текст, «скрепки» (вложения).
5.5. СКРЕПКА — меню из трёх действий: «Скан» (открывает сканер, раздел 6, прямо со
     страницы книги), «Фото» (камера или галерея устройства), «Документ» (любой файл:
     PDF, txt, docx, xlsx и т.д.). Путь хранения — только внутри папки Organizer (выход
     за пределы запрещён).
5.6. Фото с текстом (рукописный или печатный): кнопка «Распознать текст» → GLM-4.6V
     (ключ уже подключён) сохраняет рядом с картинкой файл .txt. Оригинал не трогаем.
5.7. РЕДАКТИРОВАНИЕ: любой документ книги можно отредактировать с сохранением изменений:
     название и текст записи — всегда; .txt (включая распознанный) — правка текста;
     скан/фото — поворот, обрезка, повторный фильтр, переименование, удаление;
     PDF — переименование, перестановка и удаление страниц. Правки фиксируются в
     журнале (8.5).
5.8. НАВИГАЦИЯ: на каждой странице книжки — кнопки «← Назад» (предыдущая страница)
     и «Главная книги» (алфавит). Удаление файла из записи — в «Корзину» (8.7):
     30 дней с возможностью восстановить.

6. СКАНЕР («Сделать скан» — максимальный функционал)
6.1. Вход: кнопка «Сделать скан» (камера телефона/ноутбука через браузер, без установки
     приложений).
6.2. Серия кадров → многостраничный скан; предпросмотр каждой страницы.
6.3. Обработка страницы: автоопределение границ листа с обрезкой, выравнивание
     перспективы («криво сфоткал — лист ровный»), фильтры: оригинал / чёрно-белый /
     «текст» (повышенный контраст) / цветной документ.
6.4. Результат: один многостраничный PDF или отдельные картинки; плюс текстовый слой
     .txt через распознавание (5.6).
6.5. ИМЯ ДОКУМЕНТА задаётся при создании: подставляется автоматически (дата + первые
     слова распознанного текста) и правится на месте; если имя не задали — присваивается
     автоматически «scan_ГГГГ-ММ-ДД».
6.6. ПУТИ СОХРАНЕНИЯ на выбор (галочками, можно несколько):
     — Файловая система органайзера (прикрепить к записи книжки или задаче);
     — Устройство (скачать файл);
     — Облако — Яндекс.Диск: папка /OrganizerRVA (подключение один раз, OAuth).
6.7. ССЫЛКИ НА ОБЛАКО: после сохранения на Яндекс.Диск в книжке остаётся ССЫЛКА на
     документ; документ можно читать ПРЯМО ИЗ БОТА — по команде бот (через сервер, без
     выдачи токенов в чат) забирает файл с Диска и присылает его в переписку.

7. ГЛАВНЫЙ ЭКРАН ОРГАНАЙЗЕРА
     Сегодня: задачи на день + календарь дня + счётчики (входящие, перенесённые,
     невыполненные). Кнопки: + Задача, Сделать скан, Книжка, Контакты.

8. БЕЗОПАСНОСТЬ И БЭКАПЫ
8.1. Доступ — по 5-му уровню (0.2); все действия органайзера требуют
     входа; пароли пользователей — scrypt (уже есть), сессии — общие с сайтом (30 дней).
8.2. Пароли почтовых ящиков — только в конфиге вне git (или в базе в виде, недоступном
     браузеру; в интерфейсе показывается маска, пустое поле = не менять).
8.3. Загрузка файлов: белый список расширений, лимит размера (до 25 МБ), запрет путей
     с «..», имена файлов переименовываются в безопасные. Вложения писем — те же правила.
8.4. Экранирование HTML everywhere (XSS), как на остальном сайте; действия — только
     POST/с подтверждением сессии.
8.5. Журнал действий: кто создал/закрыл/перенёс/удалил задачу и документ.
8.6. Бэкапы: таблицы органайзера — в общем data.db → попадают в ежедневные копии
     procenka/backups (14 последних, уже работает). Вложения и сканы — отдельная папка:
     ежедневное копирование в backups/files с той же ротацией; при подключении
     Яндекс.Диска — вторая копия там (защита от гибели Mac).
8.7. Удаление — в «Корзину» органайзера с хранением 30 дней, потом физически.

9. ТЕХНИЧЕСКИЕ РЕШЕНИЯ
9.1. Сервер: тот же процесс procenka/server.js; страницы — /organizer (одностраничник
     в стиле /poisk, ванильный JS).
9.2. Почтовый конвейер — ОТДЕЛЬНЫЙ фоновый процесс (procenka/mail_bot.py по образцу
     lenta_bot.py): падение почты не роняет сайт; связь — через базу/локальный API.
9.3. Таблицы в data.db: tasks, contacts (пользователи + ручные; авто-создание только
     из писем info@vredkin.ru), notebook_entries — С ПОЛЕМ ВЛАДЕЛЬЦА (книжка
     персональная), files (полиморфно: задача/запись/скан + ссылка на Диск), mailboxes
     (настройки ящиков), audit_log. Список 5-го уровня — отдельный файл в стиле
     close_people.json.
9.4. Файлы: Organizer/files/ГГГГ-ММ/… — обычная папка на диске этого компьютера,
     работает всегда. Git — это ВНУТРЕННЯЯ папка .git в проекте (хранилище версий
     кода и текстов на этом же Mac); в неё сканы/фото/документы не копируются, чтобы
     хранилище не разбухало. GitHub и ЛЮБЫЕ внешние хостинги не используются и не
     будут использоваться до полного запуска проекта — вопрос публикации решает
     директор после запуска. На VPS папка Organizer/files переносится обычным
     копированием (scp/rsync).
9.5. ЭТАПЫ (каждый принимается в работе по отдельности):
     О-1: Задачи + календарь (день/неделя, drag&drop, автоперенос, выполнено) + задачи
          из ботов. Безопасность и бэкапы — сразу.
     О-2: Почтовый конвейер (рабочий ящик) + книга контактов + звонок/письмо/сообщение.
     О-3: Записная книжка (алфавит, содержание, скрепки, распознавание текста).
     О-4: Сканер (полный) + Яндекс.Диск + личные ящики пользователей.
